# 5번 작업기록 — 대시보드 · CSS (이두규)

막히고 고친 지점을 순서대로 적었습니다. **[고침]**은 틀렸다가 바로잡은 곳, **[발견]**은 확인하다 찾은 문제입니다.
`DevelopDoc/SUBMISSION.md` ⑥ "대표 AI 활용·디버깅 사례"를 채울 때 근거로 쓸 수 있습니다.

## 1. 첫 화면 · CSS (9/29 오전)

1. **HTML을 건드리지 않고 스타일만 입힘.** 다른 사람 코드와 충돌하지 않게 기존 클래스·id에만 스타일을 입혔습니다.
2. **[고침] `styles.css`는 빈 파일이 아니었음.** `wc -l`이 0줄이라 빈 파일로 판단했는데, 실제로는 한 줄로 압축된 1,703바이트 스타일시트였습니다(`wc -l`은 줄바꿈 수만 셈). 그대로 올렸다면 기존 디자인을 통째로 덮었을 것입니다. 크기는 `wc -c`로 확인하고, 기존 한 줄은 그대로 둔 채 덧붙이기만 했습니다.
3. **[발견] 증감 색이 늘 회색.** `.kpis small`이 `.negative`보다 선택자 우선순위가 높아 빨강·초록이 덮였습니다. `.kpis small.negative`로 고쳤습니다.
4. **[발견] 오류 문구가 화면에 안 나옴.** 첫 app.js의 `status`가 `#status` 요소가 아니라 브라우저 내장 `window.status`(문자열)를 가리켰습니다.

## 2. 계획 승인 · 답변 · 로딩/실패 카드 (9/29 오후)

5. **app.js를 고치지 않고 승인 단계 끼우기.** `approval.js`가 질문 입구(질문 버튼 · 분석하기 · Enter)를 capture 단계에서 먼저 받아, [승인]을 눌렀을 때만 분석을 부릅니다.
6. **"취소하면 AI를 안 부른다"를 화면만 보고 믿지 않음.** 분석 함수 호출 횟수를 세어 확인했습니다(계획 0 → 취소 0 → 승인 1).
7. **[고침] 처리 중 오류가 화면에서 사라짐.** 성공 처리에서 난 오류를 바깥으로 넘기기 전에 "진행 중 요청" 기록을 지워, 새 요청이 있다고 오판하고 아무것도 그리지 않았습니다. 요청 실패와 응답 처리 실패를 나눴습니다.
8. **늦게 온 응답 막기.** [중단] · 새 질문 · 데이터 다시 불러오기 때 이전 요청을 `AbortController`로 끊고, 늦게 도착해도 자리 주인이 바뀌었으면 그리지 않습니다.
9. **[고침] 안내 문구가 보라 카드로 보임(두 번).** 팀 CSS의 `#answer p`가 우선해서, 카드 안 문단을 `<p>` 대신 `<div>`로 바꿨습니다.

## 3. 팀 저장소로 옮김 · 3번 데이터 · 4번 엔진 연결 (9/29 저녁)

10. **[고침] 처음 올린 곳이 팀 저장소가 아니었음.** 개인 저장소에 올렸던 PR을 `ctaleez51-art/sales-analysis`의 `part5/`로 커밋 순서대로 다시 올렸습니다(PR #3).

## 4. 4번 AI 서버 · 2번 로그인에 맞춤 (9/29 밤)

14. **서버 코드를 읽고 맞춤(실제 호출 없이).** 4번 `analyze-shop`은 `verify_jwt=true`(로그인 토큰 필요), 응답은 형식 없는 글, 실패는 400입니다. 5번은 주소 · `Authorization` 헤더 · 로그인 필요 카드 · 글 답변 표시를 맞췄습니다. 토큰 없이 요청해 401이 나오는 것으로 배포를 확인했습니다(비용 0).
15. **[발견] 하루 한도가 두 번 셈.** 4번 서버가 한도를 세게 된 뒤에도 화면이 `consumeQuota()`를 불러, 분석 1번에 2회씩 줄었습니다. 화면 쪽 호출을 뺐습니다. 서버 429는 "한도 초과" 카드로 보여 줍니다.
16. **[발견] 4번 엔진이 연속된 달만 비교하게 바뀜.** 화면 요약과 계획 카드도 엔진의 `previousPeriod`를 따르게 고쳤습니다.
17. **[헷갈림] 고쳤는데 옛 결과가 나옴.** 브라우저가 ES 모듈을 캐시에서 쓰고 있었습니다. 포트를 바꿔 새 origin으로 다시 확인했습니다.
18. **AI 대기 20초 → 60초.** PM이 측정한 응답 시간이 7~27초라, 20초로는 느린 답이 늘 시간 초과였습니다.

## 6. 열이 모자란 CSV · 필수 열 7 → 14 (9/30 새벽)

24. **[발견] 7열 CSV를 올리면 틀린 결론.** 당시 PRD 필수 7열만 있는 파일을 올리자 퍼널이 "장바구니 0 · 0.00%", 쿠팡 경쟁가 진단이 "경쟁가가 더 낮은 제품 없음"(정답 8개)으로 나왔습니다. 4번 엔진이 없는 열을 0으로 더하기 때문입니다(규칙 R1 "빈칸 ≠ 0").
25. **계산 불가 + 근거.** 그 열로 만든 값은 화면과 AI에 0 대신 "계산 불가"로 넘깁니다. 근거는 넷으로 나눕니다: 열 없음 / 일부 파일에 없음 / 빈칸 n행 / 나눌 값이 0. 경쟁가는 "진단 불가 — 없다는 뜻이 아닙니다" + 근거 + 진단 기준을 보여 줍니다. 답할 수 없는 질문 버튼은 숨깁니다.
26. **[발견] CSV 규칙과 검증 기준의 모순.** 3번 명세 28~29행은 `impressions · clicks · add_to_cart · competitor_min_price` 등을 선택 키로 두는데, 같은 파일 76행 "검증 기준 (필수)"는 그 열로 만든 CTR · 장바구니율 · 경쟁가까지 맞아야 할 값으로 둡니다. PRD §7이 이 제안안을 그대로 옮겼습니다.
27. **검증: 3번 CSV 1,200행 → 4번 엔진 → 정답표 191개.** 20열 0개, **14열 0개**, 7열 91개가 불일치했습니다. 처음에 4개가 틀려 보였던 것은 정답표가 소수 넷째 자리에서 반올림된 값이라서였고, 자릿수를 맞추니 0이었습니다.
28. **필수 열 14개로.** `csv.js` 필수 14열 · 숫자 검사 11열(PR #3). PM 문서 3곳은 PR #7로 올렸습니다. 14열은 4번 엔진이 읽는 열과 정확히 같아서, 3번 데이터와 4번 엔진은 고칠 것이 없습니다.

33. **[고침] 400 오류 카드가 다시 시도를 권함.** "잠시 뒤 다시 시도" + 파란 [다시 시도] 버튼이었는데, 400은 같은 요청을 다시 보내도 또 실패하고 한도만 1회 더 줄어듭니다. 400번대(401 · 403 · 429 제외)는 제목 "AI 서버 설정 문제" + "담당자에게 알려 주세요" + 흐린 보조 버튼 "그래도 다시 시도"로 바꿨습니다. 500번대 · 시간 초과 · 연결 실패는 그대로 [다시 시도]를 권합니다.
34. **[발견] 서버 오류 카드만 모양이 달랐음.** 카드에 종류 클래스 `sc-server`가 붙는데, 서버 메시지 줄 클래스도 `sc-server`라서 카드 전체가 코딩 글꼴 · 회색 배경 · 빨간 윗줄 없음으로 그려졌습니다. 메시지 줄을 `sc-server-msg`로 바꿨습니다.

## 반복해서 겪은 함정 (다음에 피할 것)

- **브라우저 캐시:** CSS · ES 모듈을 고쳤는데 옛 결과가 나오면 캐시부터 의심합니다(`?v=` · 새 포트).
- **선택자 우선순위:** 팀 CSS의 `#answer p`, `.kpis small`이 새 클래스를 덮습니다.
- **스크립트 속 이스케이프:** 셸 명령 안에 백슬래시가 든 치환을 넣으면 `\n` · `\1`이 깨집니다. 스크립트 파일로 따로 써서 실행합니다.
- **줄바꿈:** Windows에서 파이썬으로 쓰면 CRLF가 되어 diff가 파일 전체로 보입니다(`newline='\n'`).
- **"통과"를 눈으로만 판단하지 않기:** 호출 횟수 · 정답표 비교 · 상태 코드로 확인합니다.
- **클래스 충돌:** 종류를 클래스로 붙일 때(`sc-${kind}`) 안쪽 요소 클래스와 겹치지 않는지 봅니다. 겹치면 카드 전체가 안쪽 요소 모양이 됩니다.
- **브라우저 캐시(로컬 서버):** `python -m http.server`로 띄우면 고친 JS가 캐시로 남습니다. `fetch(파일, {cache: "reload"})` 후 새로고침합니다.
